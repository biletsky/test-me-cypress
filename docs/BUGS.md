## BUG-001 — Пошук чутливий до регістру та крайніх пробілів

| Поле | Значення |
|------|----------|
| **Severity** | Major |
| **Priority** | P1 |
| **Тип** | Functional |
| **Компонент** | Каталог / `GET /api/products?q=` |
| **Автотести** | `TM-API-CAT-004`, `TM-CAT-004` |

### Опис

Пошук за частиною назви повинен ігнорувати регістр і крайні пробіли. Фактично знаходить товар лише для запиту з правильною капіталізацією без зайвих пробілів.

### Передумови

Каталог доступний. Товар «Бездротові навушники «Орбіта»» (`p01`) існує.

### Кроки відтворення (API)

1. `GET /api/products?q=Орбіта`
2. `GET /api/products?q=орбіта`
3. `GET /api/products?q=ОРБІТА`
4. `GET /api/products?q=%20орбіта%20` (пробіли з обох боків)

### Кроки відтворення (UI)

1. Відкрити каталог.
2. У полі пошуку ввести `орбіта`, потім `  ОРБІТА  `.

### Очікуваний результат

У всіх варіантах повертається / відображається рівно 1 товар — `p01`.

### Фактичний результат

| Запит | Результат |
|-------|-----------|
| `Орбіта` | 1 товар (`p01`) |
| `орбіта` | 0 товарів |
| `ОРБІТА` | 0 товарів |
| `  орбіта  ` / `  ОРБІТА  ` | 0 товарів |

### Докази

- Скріншоти: `cypress/screenshots/products.cy.js/`
- Відповідь API для `q=орбіта`: `{"items":[],"total":0,...}` (перевірено curl, 22.10.2026)

### Вплив

Користувач не знаходить товар, якщо вводить назву в іншому регістрі або з випадковими пробілами.

## BUG-002 — Промокод WELCOME10 чутливий до регістру

| Поле | Значення |
|------|----------|
| **Severity** | Major |
| **Priority** | P0 |
| **Тип** | Functional |
| **Компонент** | Кошик / `POST /api/quote` |
| **Автотест** | `TM-API-QUOTE-002` |

### Опис

Регістр і крайні пробіли коду промокоду не повинні впливати на застосування. Фактично код приймається лише у верхньому регістрі (пробіли trim-яться коректно).

### Передумови

Робочий `X-Workspace-Token`. У кошику / тілі quote: `p01` × 1, доставка `standard`.

### Кроки відтворення

`POST /api/quote` з тілом:

```json
{
  "items": [{ "product_id": "p01", "quantity": 1 }],
  "coupon": "<код>",
  "delivery": "standard"
}
```

Перевірити коди: `WELCOME10`, `  WELCOME10  `, `welcome10`, `Welcome10`.

### Очікуваний результат

Усі коди → `200`, `discount: 24000`, `shipping: 0`, `total: 216000`.

### Фактичний результат

| Код | Статус | Відповідь |
|-----|--------|-----------|
| `WELCOME10` | 200 | знижка 240 грн |
| `  WELCOME10  ` | 200 | знижка 240 грн |
| `welcome10` | 422 | `"Невідомий промокод"` |
| `Welcome10` | 422 | `"Невідомий промокод"` |

### Докази

- Скріншоти: `cypress/screenshots/quote.cy.js/` (TM-API-QUOTE-002)
- Відтворено curl, 22.10.2026

### Вплив

Користувач, який ввів промокод у нижньому або змішаному регістрі, не отримує знижку.

## BUG-003 — Безкоштовна стандартна доставка не спрацьовує при рівно 1500 грн

| Поле | Значення |
|------|----------|
| **Severity** | Critical |
| **Priority** | P0 |
| **Тип** | Functional / Calculation |
| **Компонент** | Quote / доставка |
| **Автотест** | `TM-API-QUOTE-004` |

### Опис

Стандартна доставка має бути безкоштовною від 1500 грн **включно** (до застосування знижки). При сумі товарів рівно 1500 грн стягується 80 грн.

### Передумови

Товар `p02` «Портативна колонка «Хвиля»»: `price: 150000` (1500 грн).

### Кроки відтворення

```http
POST /api/quote
X-Workspace-Token: <token>
Content-Type: application/json

{
  "items": [{ "product_id": "p02", "quantity": 1 }],
  "coupon": "",
  "delivery": "standard"
}
```

### Очікуваний результат

```json
{
  "subtotal": 150000,
  "discount": 0,
  "shipping": 0,
  "total": 150000
}
```

### Фактичний результат

```json
{
  "subtotal": 150000,
  "discount": 0,
  "shipping": 8000,
  "total": 158000
}
```

Контрольна перевірка: при `subtotal: 165000` (`p13`) доставка вже `0` — поріг працює, але не як «включно від 1500».

### Докази

- Скріншоти: `cypress/screenshots/quote.cy.js/` (TM-API-QUOTE-004)
- curl, 22.10.2026

### Вплив

Клієнт переплачує 80 грн на межі безкоштовної доставки. Розбіжність із маркетинговим текстом сайту («від 1 500 ₴»).

## BUG-004 — Повторне скасування замовлення повертає 200 замість 409

| Поле | Значення |
|------|----------|
| **Severity** | Major |
| **Priority** | P0 |
| **Тип** | Functional / Idempotency of cancel |
| **Компонент** | Замовлення / `POST /api/orders/{id}/cancel` |
| **Автотест** | `TM-API-ORD-003` |

### Опис

Перше скасування має змінити статус на `cancelled`. Повторне скасування того самого замовлення має повертати `409`. Фактично другий запит знову повертає `200`.

### Передумови

Створено замовлення зі статусом `confirmed` у поточному workspace.

### Кроки відтворення

1. `POST /api/orders` (approved) → зберегти `id`.
2. `POST /api/orders/{id}/cancel` → очікується `200`, `status: cancelled`.
3. Повторити `POST /api/orders/{id}/cancel`.

### Очікуваний результат

Крок 2: `200`, `cancelled`.  
Крок 3: `409`.

### Фактичний результат

Крок 2: `200`, `{"id":"...","status":"cancelled"}`.  
Крок 3: знову `200`, `{"id":"...","status":"cancelled"}`.

### Докази

- Скріншоти: `cypress/screenshots/orders.cy.js/` (TM-API-ORD-003)
- curl, 22.10.2026

### Вплив

Клієнт / інтеграція не може надійно відрізнити «вже скасовано» від успішної операції; порушена контрактна семантика 409.

## BUG-005 — Валідація імені при оформленні не враховує trim

| Поле | Значення |
|------|----------|
| **Severity** | Major |
| **Priority** | P0 |
| **Тип** | Validation |
| **Компонент** | Замовлення / `POST /api/orders` |
| **Автотест** | `TM-API-ORD-006` (name with 1 char after trim) |

### Опис

Ім'я повинно містити 2–80 символів **після trim**. Значення `"  А  "` (1 літера після trim) приймається, замовлення створюється з `201`.

### Передумови

Валідний workspace token, товар у наявності (наприклад `p01` × 1).

### Кроки відтворення

```http
POST /api/orders
X-Workspace-Token: <token>

{
  "items": [{ "product_id": "p05", "quantity": 1 }],
  "delivery": "standard",
  "name": "  А  ",
  "email": "test@example.test",
  "address": "Київ, вул. Тестова, 12",
  "payment": "approved"
}
```

### Очікуваний результат

`422`, замовлення не створюється.

### Фактичний результат

`201`, статус `confirmed`. У списку замовлень з’являється новий запис.

Примітка: для адреси `"   Київ   "` (4 символи після trim) API коректно повертає `422`. Проблема саме в полі `name`.

### Докази

- Скріншоти: `cypress/screenshots/orders.cy.js/` (TM-API-ORD-006)
- curl, 22.10.2026

### Вплив

Можливі замовлення з невалідним коротким ім’ям, обійшовши заявлені правила валідації.

## BUG-006 — Повторне додавання «Фокус» (p07) створює другий рядок у кошику

| Поле | Значення |
|------|----------|
| **Severity** | Major |
| **Priority** | P1 |
| **Тип** | Functional |
| **Компонент** | Кошик (UI + `localStorage`) |
| **Автотест** | `TM-CART-001` |

### Опис

У кошику має бути одна позиція на `product_id`: повторне «До кошика» збільшує кількість. Для товару `p07` («Таймер «Фокус»») створюється другий рядок із тією ж `product_id`.

У клієнтському коді (`assets/lab.js`) є явна гілка:

```js
if (existing && id !== 'p07') existing.quantity++;
else cart.push({ product_id: id, quantity: 1 });
```

### Передумови

Нове середовище. Товар `p07` видно в каталозі (категорія Workspace).

### Кроки відтворення

1. Відкрити каталог, категорія «Робочий простір».
2. Двічі натиснути «До кошика» на «Таймер «Фокус»».
3. Відкрити кошик.

### Очікуваний результат

1 рядок, кількість = 2, лічильник кошика = 2.

### Фактичний результат

2 рядки з `p07`, у кожному кількість 1 (лічильник показує 2).

Контроль: для інших товарів (наприклад `p01`) поведінка коректна — один рядок.

### Докази

- Автотест: `cypress/e2e/ui/cart.cy.js` → TM-CART-001
- Відтворення вручну в UI; підтверджено аналізом `lab.js`

### Вплив

Некоректний кошик, можливі проблеми з quote / оформленням (дубльовані позиції на API відхиляються з 422).

## BUG-007 — Застосований промокод не зберігається після reload

| Поле | Значення |
|------|----------|
| **Severity** | Major |
| **Priority** | P1 |
| **Тип** | Functional / Persistence |
| **Компонент** | Кошик / промокод |
| **Автотест** | `TM-CART-007` |

### Опис

Кошик і застосований промокод мають зберігатися після reload. Кошик зберігається (`localStorage` → `cart`), а код купону — ні: після оновлення сторінки знижка зникає.

### Передумови

Нове середовище. У каталозі доступний `p01`.

### Кроки відтворення

1. Додати «Орбіта» до кошика.
2. Відкрити кошик, ввести `WELCOME10`, «Застосувати».
3. Переконатися: знижка 240 грн, разом 2160 грн.
4. Оновити сторінку (F5 / reload).
5. Відкрити кошик знову.

### Очікуваний результат

Позиція `p01` на місці; знижка 240 грн; разом 2160 грн.

### Фактичний результат

Позиція `p01` на місці; знижка 0; разом 2400 грн. Поле промокоду порожнє.

Технічна причина: у `localStorage` ключ `test-me:v2` зберігає `{ token, cart, compare }`, поле `coupon` не персиститься.

### Докази

- Автотест: `cypress/e2e/ui/cart.cy.js` → TM-CART-007
- DevTools → Application → Local Storage

### Вплив

Після випадкового reload користувач втрачає знижку і може оформити замовлення за повною ціною, думаючи, що промокод ще активний.

## BUG-008 — У порівнянні одна характеристика розбивається на два рядки

| Поле | Значення |
|------|----------|
| **Severity** | Minor |
| **Priority** | P2 |
| **Тип** | Functional / Data consistency |
| **Компонент** | Порівняння товарів |
| **Автотест** | `TM-CMP-004` |

### Опис

Порівняння має показувати спільні характеристики одним рядком; відсутнє значення — «—». Через різний символ апострофа в ключах specs (`З'єднання` vs `З’єднання`, U+0027 vs U+2019) утворюються два рядки, у кожному частина клітинок — «—».

### Передумови

Товари `p01` (Орбіта) і `p14` (Ритм) у каталозі Audio.

### Кроки відтворення

1. Додати до порівняння `p01` і `p14`.
2. Натиснути «Порівняти».
3. Переглянути рядки з назвою, що містить «єднання».

### Очікуваний результат

Один рядок «З'єднання» з двома заповненими значеннями (Bluetooth тощо).

### Фактичний результат

Два рядки (різні апострофи); у кожному один товар має значення, інший — «—».

### Докази

- Автотест: `cypress/e2e/ui/compare.cy.js` → TM-CMP-004
- Дані specs у `GET /api/products` для `p01` / `p14`

### Вплив

Таблиця порівняння вводить в оману: виглядає, ніби в одного з товарів немає характеристики з’єднання.
